# lazygitrs — Repository Audit & Improvement Plan

**Date:** 2026-11-04 · **Revision audited:** `d532f60f4` (`0.1.5-cockpit`) · **Fork:** `fcmiranda/lazygitrs` (upstream `Blankeos/lazygitrs`)

Everything below was measured on this machine against this checkout unless it is marked *estimate*. Commands used are listed in [Appendix A](#appendix-a--how-the-numbers-were-measured) so the numbers can be reproduced.

---

## 0. Executive summary

| Area | Grade | One-line verdict |
| :--- | :---: | :--- |
| Security | **D** | The unauthenticated localhost HTTP API (`acp.rs`) accepts a shell command that is later run by a shell. A web page can forge the request. |
| Runtime performance | **C** | Rendering is fast, but at idle it runs **~10 git processes per second**. Every 10 s tick does **two** full model reloads, including **network `ls-remote` calls**. |
| Correctness | **B** | 323/323 tests pass. One keybinding is dead (`files.generateAiCommit` is shadowed by a hardcoded `Ctrl+G`). |
| Code health | **C** | `gui/mod.rs` is 12.6 k lines, `Gui` has ~235 fields, `handle_key` is 417 lines. 306 clippy and 56 rustc warnings. |
| Dependencies | **C** | `tokio 1.53.1` is affected by RUSTSEC-2026-0386. `serde_yaml` is deprecated (unmaintained `unsafe-libyaml`). |
| CI / Release | **D** | No CI runs on push or PR (no fmt, clippy, test or deny). The release matrix uses the retired `macos-13` runner. `dist-workspace.toml` is stale. |
| Config | **B−** | Config is lazygit-compatible, but typos are silently ignored and there is no schema. Some defaults use `Alt`. |
| Docs | **C** | Plenty of docs, but test fixtures and scratch files are committed. Some README claims are unmeasured, the versions disagree, and the fork's install path points at upstream builds. |
| TUI ergonomics | **B+** | Strong vim/home-row design. Weak spots: `Alt` defaults for panel resizing, an opaque selection strip, red/green used for passive chrome, and status-bar hints with no separators. |

**The three fixes with the most impact:**
1. Lock down `/session-api` with a token and a content-type check, and shell-escape `sessionId`.
2. Fix the double refresh and take `ls-remote` out of the periodic refresh. This removes about 75 % of idle git process spawns and all idle network traffic.
3. Add a CI workflow (`fmt --check`, `clippy -D warnings` for a new-warnings baseline, `test`, `cargo deny`), then run `cargo update -p tokio`.

## 2. Findings

Severity: **P0** = fix now (security or obvious waste) · **P1** = next sprint · **P2** = structural / ongoing.

### P0-1 — Remote command execution through the AI-notes HTTP API
**Where:** `src/acp.rs:244-249` (routes), `:398-480` (`register`), `src/gui/mod.rs:10199-10236` (execution).

- `POST /session-api` has no authentication. `{"action":"register","notifyCommand":"…"}` stores an arbitrary shell command. That command runs the next time the user presses `S` on a note.
- The handler reads the raw `Bytes` and parses JSON **whatever the `Content-Type` is**. A browser sends a cross-origin `text/plain` POST as a "simple request" with no CORS preflight. Any web page the user opens can therefore plant the command (CSRF). The `GET` endpoints are also exposed to DNS rebinding.
- `{{session_id}}` is substituted **without** `shell_escape_arg`, unlike `{{workspace_path}}` and `{{prompt}}`. A crafted `sessionId` can inject commands even when the user picked the notify command themselves.
- The value is persisted to `.lines.json` in the repo. A cloned repo that contains a malicious `.lines.json` brings its own notify command (supply-chain angle).

**Fix:**
1. Generate a random token at startup and write it next to `.lazygitrs.port` (mode 0600). Require `Authorization: Bearer <token>` on every route.
2. Reject requests whose `Content-Type` is not `application/json`, and requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>`. This closes both CSRF and DNS rebinding.
3. Escape `{{session_id}}`, or validate it against `^[A-Za-z0-9._:-]{1,128}$`.
4. Never take `notifyCommand` from `.lines.json` or HTTP without confirming it with the user. Show a one-time popup: "AI client wants to run: `…` — allow? y/n". Better still, only allow commands from user config (`git.ai.notifyCommand`).

### P0-2 — Double full refresh every 10 s
**Where:** `src/gui/mod.rs:1922-1935` and `:1803`.

`last_refresh_at` is reset only when a refresh **finishes** (`:1803`). While a refresh is in flight (~1.6 s), every loop iteration sees `elapsed() >= 10` and sets `needs_refresh = true` again. As soon as the first refresh lands, a second identical one starts. This wastes 50 % of all periodic git work.

**Fix (two lines):** don't re-arm while a refresh is in flight, or stamp the time at start:
```rust
if self.config.user_config.git.auto_refresh
    && refresh_interval > 0
    && !self.refresh_in_progress            // ← add
    && self.last_refresh_at.elapsed().as_secs() >= refresh_interval
```
Add a regression test: simulate one in-flight refresh across loop ticks and assert that `start_background_refresh` is called once.

### P0-3 — Network I/O and history walks inside the periodic refresh
**Where:** `src/git/tag.rs:26,55-106`, `src/git/mod.rs:166-290`, `src/git/remote.rs:323-329`.

- `load_tags()` runs `git ls-remote --tags <remote>` **for every remote, one after another, on every refresh**. That is network traffic every 10 s, an SSH handshake per remote, and a 3 s timeout per remote when offline (6 s+ per refresh with two remotes).
- After a timeout, the detached thread and its `git`/`ssh` child are **never killed**. On a flaky network they pile up.
- `shortlog -sn -e HEAD --max-count=500`, `log --all --max-count=300`, `submodule status`, `worktree list` and `remote -v` also run every 10 s. They almost never change between ticks.
- Upstream lazygit's `refreshInterval` refreshes **files only**. Full scopes refresh after user actions or `fetch`.

**Fix:**
- Split the work into **refresh scopes**, as upstream does: `Files` (on the interval), `Refs` (after a fetch, a checkout or a `.git/HEAD`/`refs` mtime change), `Remote` (only after `fetch`/`push`, or on demand when the Tags panel opens), and `Static` (contributors, repo URL, remotes: once per session plus after remote operations).
- Cache the `ls-remote` result per remote with a TTL equal to `fetchInterval`. Run remotes in parallel. Kill the child on timeout (keep the `Child` handle; call `child.kill()`).
- Optional: gate refreshes on `stat()` of `.git/index`, `.git/HEAD` and `.git/refs`. If nothing changed, do nothing. This costs zero processes per tick at true idle.

**Expected result:** idle drops from ~104 to ≤6 git processes per 30 s (one `status` per tick), with no network traffic. *Estimate.*

### P0-4 — Dependency advisories
- **RUSTSEC-2026-0386** (unsound `tokio::io::unix::AsyncFd` constructors) affects `tokio 1.53.1`. Fix: `cargo update -p tokio` (≥ 1.53.3).
- **RUSTSEC-2024-0449**: `unsafe-libyaml` is unmaintained, pulled in by `serde_yaml 0.9.34+deprecated`. Migrate to `serde_yaml_ng` or `serde_norway`, which are API-compatible drop-ins. `serde_saphyr` is a pure-Rust option. Keep the lazygit YAML format.

### P1-1 — No CI quality gate; release pipeline drift
- `.github/workflows` only has `release.yml` (tags) and `publish-registries.yml`. `publish-registries.yml` is gated to `github.repository == 'Blankeos/lazygitrs'`, so it **never runs on this fork**. Nothing runs fmt, clippy, tests or audits on a push or PR.
- `release.yml` uses `macos-13` for `x86_64-apple-darwin`. GitHub has retired that runner image, so the job will queue forever or fail. Use `macos-latest` with `--target x86_64-apple-darwin` (cross-compiling on Apple Silicon works), or `macos-15-intel`.
- `dist-workspace.toml` configures cargo-dist (`*-linux-gnu` targets, Homebrew tap), while `release.yml` uses `taiki-e/upload-rust-binary-action` (`*-linux-musl`). Two release systems that disagree. Delete whichever one is unused.
- Versions disagree: `Cargo.toml 0.1.5`, `npm/package.json 0.0.38`, `CHANGELOG [0.1.5-cockpit]`. Tags `blah`, `latest` and `0.8.3` look accidental.
- There is no `rust-version` (MSRV). `edition = "2024"` needs ≥ 1.85. Declare it so `cargo` gives a clear error on older toolchains.

**Fix:** add `.github/workflows/ci.yml`. A minimal job list:
```yaml
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with: { components: "rustfmt, clippy" }
      - uses: Swatinem/rust-cache@v2
      - run: cargo fmt --check
      - run: cargo clippy --all-targets -- -D warnings   # after the P2-2 cleanup
      - run: cargo test --locked
      - uses: EmbarkStudios/cargo-deny-action@v2
        with: { command: check advisories bans licenses }
```

### P1-2 — `Ctrl+G` hardcoded; remapping is impossible and one binding is dead
**Where:** `src/gui/mod.rs:4212-4217`, `src/config/keybindings.rs:193,251`, `src/gui/controller/files.rs:111`.

- The universal handler matches `toggle_working_tree_and_head` **or** a hardcoded `Ctrl+g`/`Ctrl+G`, and it runs before the Files controller. So `files.generateAiCommit` (default `<c-g>`) can **never fire**, and remapping the toggle to `<c-t>` still leaves `Ctrl+G` hijacked. The `quick_ai_note` handler right below it uses the same hardcoded-fallback pattern.
- **Fix:** remove the hardcoded fallbacks and rely only on `matches_key(&config)`. Change the default for `files.generateAiCommit` to a free key (see the cost matrix in §6). At config load, add a check that reports keys bound twice in contexts that overlap.

### P1-3 — Hardcoded personal path in the custom-command runner
`src/gui/controller/custom_commands.rs:83` sources `~/.dotfiles/main/git/.zsh/packages/git.zsh` for every user. Replace it with a config key `customCommands.shellInit: [paths]`, defaulting to `[]`. Even better, run `$SHELL -ic` and let the user's rc files handle it.

### P1-4 — The render loop redraws unconditionally
**Where:** `src/gui/mod.rs:1866-1912, 1957-1970`.

- Every loop iteration calls `terminal.draw()`, whether or not anything changed. The wake-up interval is 16 ms when anything is async, 50 ms when `autoRefresh` is on (the default), and 200 ms otherwise. So the default idle rate is **20 full view rebuilds per second**. Ratatui's buffer diff keeps terminal *output* small, but the CPU cost of building every widget (89 `format!` calls in `views.rs`, syntax-highlighted diff panes) is paid each time. This is part of the 3.5 % idle CPU.
- With `gui.outerFrame: true`, every frame also clones the **entire** off-screen buffer cell by cell (`buf[(x,y)] = done.buffer[(x,y)].clone()`).
- **Fix:** add a `dirty: bool`. Set it on input, resize, async result, spinner tick (only while a spinner is visible), or a model change. Skip `draw()` when it is not set. Render the outer frame by drawing straight into `inner` with `frame.render_widget` on a sub-`Rect` (ratatui widgets take an area, so the off-screen terminal is unnecessary). The spinner should advance on wall-clock time, not on loop count.
- **Expected:** idle CPU drops from ~3.5 % to under 0.3 %. Laptop battery life improves on a tool that stays open all day inside tmux. *Estimate.*

### P1-5 — Blocking git calls on the UI thread
`after_model_refresh` (`src/gui/mod.rs:10971-11030`) runs `load_commits_for_branch(…, 300)` and `commit_files()` **synchronously** while holding the `model` mutex. `refresh()` (`:10942`) runs the whole `load_model` synchronously. In a large repo (100 k+ commits, monorepo), this blocks input for hundreds of ms, past the 100 ms Doherty threshold. There are 45 `self.git.*` call sites under `src/gui/`. Audit each one: anything that may spawn git on a keypress should go through the existing streaming/background channels.

### P1-6 — Configuration ergonomics
- `#[serde(default)]` without unknown-key reporting means `gui.borderGradiant: aurora` (typo) is **silently ignored**. Use `serde_ignored` to collect unknown paths and show them once in the command log or a toast at startup. Don't fail hard, so lazygit config compatibility is kept.
- Ship a JSON Schema (`schemars` on `UserConfig`) and document `# yaml-language-server: $schema=…`. Editors then autocomplete and validate the config.
- Panel-resize defaults are `Alt` chords (`<a-h> <a-l> <a-k> <a-j> <a-r>`, `keybindings.rs:186-190`). They are kept for lazygit compatibility, but see §2/§6 for a home-row alternative offered as an *added* binding, so existing muscle memory isn't broken.

### P2-1 — God object and file size
- `gui/mod.rs`: 12.6 k lines, 228 functions, `struct Gui` ~235 fields, `handle_key` 417 lines. `views.rs` is 5 k lines, `side_by_side.rs` 5.6 k.
- Plan, in order of lowest risk first:
  1. Move `#[cfg(test)]` blocks into `mod.rs`-sibling `tests.rs` files (about 1.5 k lines out of `gui/mod.rs`). Clippy already flags "items after a test module" ×5.
  2. Group `Gui` fields into sub-structs that already exist conceptually: `RefreshState`, `AcpState`, `CommitFilterState`, `FileTreeState`, `RemoteOpState`, `EditorHandoff`.
  3. Turn `handle_key` into a dispatch table: `(ContextId, KeyAction) -> fn(&mut Gui)`. Precedence then lives in data, which makes the shadowing in P1-2 testable.
  4. Split `views.rs` by panel. `presentation/` already exists, so move the remaining render functions there.
- 174 `lock().unwrap()` calls on `Arc<Mutex<Model>>`. A panic on any background thread poisons the mutex and crashes the UI on the next frame. Use `parking_lot::Mutex` (no poisoning), or `.lock().unwrap_or_else(PoisonError::into_inner)`.

### P2-2 — Warning debt
- `cargo clippy --fix --allow-dirty` then `cargo fmt` clears most of the 121 `collapsible_if` and the mechanical lints. Review the 17 `manual_clamp` cases by hand: `.min(60).max(30)` → `.clamp(30, 60)` panics only if min > max, and that isn't the case here.
- Real bug candidate: `side_by_side.rs:5535` `if … { 3 } else { 3 }`. Either a branch was meant to differ or the `if` should go.
- Dead code: variants `Staging`, `Merged/Rebasing/Selected/Conflicted`, `Content/UnifiedDiff`, `HunkCommentary`, `Both`, plus structs `DiffHunk` and `BisectInfo`. Delete them or wire them up.
- `ratatui_image::Picker::from_fontsize` is deprecated (×3). Migrate to `Picker::from_query_stdio()` with a `halfblocks()` fallback. Keep the probe off the Helix nested-tty path (`gui/mod.rs:12472` already documents the race).
- Add `[lints]` to `Cargo.toml` so the policy is versioned:
  ```toml
  [lints.rust]
  unsafe_op_in_unsafe_fn = "warn"
  [lints.clippy]
  collapsible_if = "allow"   # stylistic; revisit later
  too_many_arguments = "allow"
  ```

### P2-3 — Dependency hygiene
- `once_cell` → `std::sync::LazyLock` (4 uses). That removes one crate.
- `tokio = { features = ["full"] }` is only used by the `axum` server in `acp.rs`. Narrow it to `["rt", "net", "sync", "macros", "time"]`. Optional: feature-gate the whole ACP server (`--features ai-notes`, on by default) so a minimal build drops axum and tokio (~60 crates).
- The tree-sitter grammars (0.23/0.24) lag behind current releases, and they are most of the 15 MB binary. Consider a `syntax-full` feature. `cargo bloat --release --crates` will confirm the split.

### P2-4 — Testing strategy
- Every test is a unit test. Add `tests/` integration tests that build throwaway repos with `git init` in a `tempfile::TempDir`, then drive `Gui` with `TestBackend`. Several `terminal_mouse_tests` already do this internally, so promote the pattern.
- Snapshot tests for rendered panels (`insta` + `TestBackend` buffer → string). These catch visual regressions in the status bar, help and diff layout. That matters because `AGENTS.md` requires keeping the Help popup and the status-bar hints in sync. A snapshot makes that enforceable.
- A perf regression test: run the git shim from Appendix A in CI, start the app for 25 s, and assert that idle git processes are ≤ N. This locks in the P0-2 and P0-3 wins.

## 3. TUI ergonomics audit (tui-ux-architect protocol)

### 3.1 KLM-GOMS diagnosis

| Flow | Current | Proposed | Δ |
| :--- | :--- | :--- | :--- |
| Generate an AI commit from Files | `c` → popup → AI key inside the commit popup (`commit_message.aiGenerate` `<c-g>`). The direct `Ctrl+G` is dead (P1-2). | Resize the side panel | `Alt+H` / `Alt+L`: thumb adduction under the palm on a MacBook, ulnar deviation. T_K ≈ 280 ms, high RSI risk | *Add* `Ctrl+W h/l` (vim window idiom, CapsLock+W inward roll), keeping `Alt` for compatibility. T_K ≈ 240 ms, H=0 | removes the `Alt` dependency |

### 3.2 Home-row and vim validation
- ✅ `hjkl`, `{}`/`[]` hunk travel, `,` `.` `<` `>` tree traversal, and `1-5` panel jumps all keep H = 0.
- ✅ Cascading `Esc`. ⚠️ At the Files root, `Esc` **quits the app** (`gui/mod.rs:4202-4208`). This is intended for popup use, but in a full-screen session one extra `Esc` while unwinding (diff → files → *exit*) loses context. Suggestion: quit on `Esc` at the root only when `--popup`/outer-frame mode is active, or require a double-tap within 400 ms (the code already uses an armed-timestamp pattern at `:3510`).
- ❌ `Alt` dependencies: panel resize (5 bindings). Add non-Alt alternatives (§6). Don't remove the old ones (ergonomic stability).
- ✅ `keyd` CapsLock (Ctrl hold / Esc tap) works with every `Ctrl+` binding, since none needs Shift+Ctrl.

## 4. Improvement plan

Each phase can ship on its own. Acceptance criteria are measurable with Appendix A.

### Phase 1 — Safety and waste (1–2 days) — **done on `audit/phase-1`**

> Result (measured with Appendix A): idle git calls 104 → 58 per 30 s, idle `ls-remote` 2/tick → 0, `cargo deny check advisories` passes, tests 323 → 333.
> Change from the plan for 1.1: **no bearer token.** Every existing client (the skill, README, `--clear-session`, the antigravity hook) already sends JSON to loopback. The Host and Content-Type checks alone close the browser paths (CSRF, DNS rebinding) without breaking those clients. A token would only defend against same-user local processes, and those can already edit the config. Instead of confirm-before-run, a `notifyCommand` from a working-tree `.lines.json` is ignored.
> 1.4 used `serde_norway`, not `serde_yaml_ng`: `serde_yaml_ng` still depends on `unsafe-libyaml`.

> **The main finding was not the one this audit predicted.** P1-4 blamed unconditional redraws. Per-thread accounting showed the **input-reader thread** used ~85 % of idle CPU. This is worth reporting upstream to crossterm/filedescriptor. Fix: wait 1 s per call, and have `pause()` wake the reader by raising `SIGWINCH` (crossterm's resize pipe). The editor handoff was checked against a baseline build: keys reach the editor, and lazygitrs takes input again afterwards.
>
> Changes from the plan:
> - **3.2: no dirty flag.** Tracking ~15 async receive paths risks stale frames. The loop wake cadence follows what is on screen instead (16 ms busy, 50 ms for 2 s after input or while an un-flagged spinner shows, ≤1 s idle). The spinner runs on wall-clock time. The outer-frame copy was not changed, because at ≤1 frame/s idle it no longer matters.
> - **3.1:** a `stat()` fingerprint gates full reloads. The index is left out of it on purpose.
> - **3.3: only the network-bound UI-thread calls moved** (submodule add/update). The remaining real blocker is `after_model_refresh` (`commit_files`, `load_commits_for_branch`). With the fingerprint gate it now runs only after real git changes.
> - **3.4:** time to first frame is measured from outside (table above). The README `--version` benchmark is upstream-generated (`just gen-benchmarks`) and was left alone.
> - **3.5:** tokio is narrowed to `rt, net, sync, time` (−2 crates only, because axum pulls in the rest). `ai-notes` / `syntax-full` feature gates are not done.
> - New hygiene finding: lazygitrs writes `.lazygitrs.port` into the worktree root of every repo it opens, so it shows up as untracked in other people's repos. Moving it to `.git/` needs a coordinated change to every client (skill, hooks, README), so it is left for a follow-up.

**ACP request guard (P0-1)** — axum middleware sketch
```rust
async fn guard(
    State(st): State<AppState>,
    req: axum::extract::Request,
    next: axum::middleware::Next,
) -> Result<axum::response::Response, StatusCode> {
    let h = req.headers();
    let host_ok = h.get(HOST).and_then(|v| v.to_str().ok())
        .is_some_and(|v| v == st.expected_host_ip || v == st.expected_host_localhost);
    let auth_ok = h.get(AUTHORIZATION).and_then(|v| v.to_str().ok())
        .and_then(|v| v.strip_prefix("Bearer "))
        .is_some_and(|t| constant_time_eq(t.as_bytes(), st.token.as_bytes()));
    let ct_ok = req.method() != Method::POST
        || h.get(CONTENT_TYPE).and_then(|v| v.to_str().ok())
            .is_some_and(|v| v.starts_with("application/json"));
    if !host_ok { return Err(StatusCode::FORBIDDEN) }
    if !auth_ok { return Err(StatusCode::UNAUTHORIZED) }
    if !ct_ok   { return Err(StatusCode::UNSUPPORTED_MEDIA_TYPE) }
    Ok(next.run(req).await)
}
```
